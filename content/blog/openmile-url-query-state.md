## 개요

| 항목 | 내용 |
|---|---|
| 유형 | 설계 판단 |
| 시점 | BOS 신규 개발 과정 |
| 상태 | 개발·테스트 단계에 반영 |
| 관련 영역 | 목록 화면, 필터, 페이지 처리, URL 쿼리스트링 |
| 나의 역할 | URL 상태 보존 판단, 공통 훅 `useGridData` 구성 |

## 1. 상황과 제약

BOS 페이지 56개는 대부분 목록(Management)·등록(Create)·상세(Detail) 세 가지 형태가 반복됐습니다. 어드민에서는 운영자가 조건을 걸어 조회한 뒤 상세로 들어갔다 돌아오거나 새로고침하는 일이 잦습니다.

조회 상태가 화면 안에만 있으면 그때마다 조건을 다시 입력해야 하고, 같은 결과 화면을 다른 사람에게 링크로 전달할 수도 없습니다. 요구사항에는 이 부분이 없었습니다.

## 2. 검토와 판단

운영자가 URL만으로 같은 조회 결과를 다시 열 수 있어야 어드민을 편하게 쓸 수 있다고 봤고, 요청이 없었지만 직접 넣기로 했습니다.

| 구분 | 화면 안에만 두는 경우 | URL에 담는 경우 |
|---|---|---|
| 새로고침·뒤로가기 | 조회 조건이 초기화됨 | 조회 조건이 유지됨 |
| 결과 공유 | 조건을 말로 전달해야 함 | 링크로 같은 결과를 열 수 있음 |

## 3. 실행과 조율

- 목록 화면의 조회·필터·페이지 처리를 공통 훅 `useGridData`로 묶었습니다. 페이지는 조회 경로, 필터 초기값, 컬럼 정의만 넘깁니다.
- 필터·페이지·페이지 크기를 URL 쿼리스트링에서 읽어 초기값으로 쓰고, 값이 바뀌면 다시 URL에 기록하게 했습니다.
- 컬럼 정의에는 `grid-util`의 필터 유형(숫자·텍스트·날짜), 용도별 고정 폭, 컬럼 타입을 공통으로 썼습니다.

## 4. 결과와 확인

목록 화면에서 새로고침하거나 뒤로가기를 해도 조회 조건이 유지되고, 조회 결과를 링크로 공유할 수 있게 됐습니다. 새 목록 화면은 조회 경로와 필터 초기값, 컬럼 정의만 정하면 같은 방식으로 동작합니다.
