## 개요

| 항목 | 내용 |
|---|---|
| 유형 | 업무 흐름 개선·기획 및 디자인 협업 |
| 시점 | 관리자 페이지 리뉴얼 과정 |
| 상태 | 리뉴얼에 반영 |
| 관련 영역 | 상·하위 요소 생성 흐름, 사용자 크레딧 지급 탭 |
| 나의 역할 | PL·프론트엔드 개발, 기존 업무 흐름의 불편함 확인과 기획·디자인 논의 참여 |

## 1. 상황과 제약

기존 관리자에서는 상위 요소를 만들다가 하위 요소가 필요하면, 하위 요소 페이지로 가서 먼저 만든 뒤 상위 요소 화면으로 돌아와 선택해야 했습니다. 작업 하나에 필요한 기능이 여러 페이지에 흩어져 있어서 페이지를 계속 오가야 했습니다.

크레딧 지급도 마찬가지였습니다. 크레딧 페이지에서 지급할 크레딧을 먼저 만들고, 사용자 페이지로 옮겨 가서 지급했습니다.

## 2. 검토와 판단

리뉴얼에서는 상위 요소를 만드는 화면 안에서 필요한 하위 요소도 바로 만들 수 있게 바꿨습니다. 관련 요소를 준비하려고 다른 페이지에 다녀오는 번거로움을 줄이려는 목적이었습니다.

크레딧은 사용자 크레딧 지급 탭에서도 만들고 지급할 수 있게 했습니다.

| 구분 | 처리 흐름 |
|---|---|
| 기존 | 크레딧 페이지에서 생성 → 사용자 페이지로 이동 → 크레딧 지급 |
| 추가한 경로 | 사용자 크레딧 지급 탭에서 크레딧 생성 → 같은 탭에서 지급 |

기존 크레딧 페이지는 그대로 두고, 사용자 화면에서 생성과 지급을 처리하는 경로를 하나 더 만들었습니다.

이 변경을 빠르게 적용하는 데는 FSD 구조가 도움이 됐습니다. 크레딧 생성에 필요한 모달 UI와 내부 API 로직이 이미 `features`로 분리되어 있어, 사용자 크레딧 지급 탭에서도 기존 기능을 그대로 재사용했습니다. 모달 UI와 API 로직을 새로 만들 필요가 없어서 생성과 지급을 잇는 흐름에 집중할 수 있었습니다.

## 3. 실행과 조율

기획·디자인 과정에 참여해 기존 관리자 페이지의 불편한 점과 고칠 부분을 논의했습니다. 하위 요소를 만드는 화면과 그 요소를 쓰는 화면이 나뉘어 있던 흐름을 고쳤고, 크레딧 생성과 지급은 사용자 크레딧 지급 탭에서도 할 수 있게 했습니다.

저는 PL이자 관리 영역 전체의 화면 개발 담당으로 참여했습니다.

## 4. 결과와 확인

이제 사용자 크레딧 지급 탭에서 크레딧 생성과 지급을 이어서 할 수 있습니다. 이 경로로 작업하면 크레딧을 만들러 크레딧 페이지에 따로 갈 필요가 없습니다.
