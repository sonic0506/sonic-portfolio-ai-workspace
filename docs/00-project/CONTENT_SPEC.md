# Content Specification

## 1. Project

### 기본 정보

- 제목
- 한줄 요약
- 핵심 요약: 여러 항목의 리스트
- 기간
- 기여도
- 담당 포지션
- 썸네일
- 공개 상태
- 대표 프로젝트 여부
- 사용한 기술들: 공통 기술 목록에서 선택
- GitHub 링크 / 서비스 링크
- 관련 내부 블로그글들: 기존 글을 선택하여 연결

### 목록 표시

| 항목 | 대표 | 비대표 |
|---|---|---|
| 제목 / 한줄 요약 | 표시 | 표시 |
| 핵심 요약 리스트 | 표시 | 미표시 |
| 기간 / 기여도 / 담당 포지션 | 표시 | 표시 |
| 썸네일 | 표시 | 미표시 |
| 사용한 기술들 | 표시 | 표시 |
| 공개 상태 / 대표 여부 | 방문자에게 미표시 | 방문자에게 미표시 |
| GitHub·서비스 링크 / 관련 블로그 | 지정 목록에 없음 | 지정 목록에 없음 |
| 상세 설명 섹션 | 미표시 | 미표시 |

대표와 비대표는 목록에서 구분해 표시한다. 비대표 목록에서 생략한 필드가 데이터에서 삭제되는 것은 아니다. 공개 상태와 대표 여부는 관리용 상태/분류이며 방문자에게 별도 배지나 필드로 노출하지 않는다. Public에는 공개 프로젝트만 노출한다는 기존 정책을 유지한다.

### 상세 설명

- 여러 섹션으로 구성하며 각 섹션은 제목 + Markdown 본문이다.
- 섹션 본문 안에 추천 질문 블록을 삽입할 수 있다. 첨부 이미지처럼 질문 여러 개를 버튼/칩 형태로 표현하는 구조를 참고한다.
- 제목은 다음 프리셋 선택 또는 직접 입력을 지원한다: 개요, 배경 · 문제, 역할 · 기여도, 기술 선택 이유, 주요 작업, 트러블슈팅, 성과, 배운 것, 아쉬운 점 · 다시 한다면.
- 이미지의 소제목/문단은 Markdown 표현 참고이며 별도 입력 필드를 강제하지 않는다.
- 추천 질문 클릭 시 새 채팅 세션을 열고 해당 질문을 즉시 챗봇에 전송한다. 기존 대화 이력은 새 세션으로 가져오지 않는다. 저장 문법, 삽입 위치 모델, 관련 원문/섹션 맥락 전달 방식은 후속 설계한다.
- 대표 여부는 목록 표현을 구분하며 비대표 상세 입력을 금지하는 정책은 요청되지 않았다.

## 2. Shared Skill Catalog

- Admin에서 기술 명칭을 등록/관리하고 Project, Blog, Profile에서 같은 기술 항목을 참조한다.
- 기존 Skill 개념을 재사용한다. 프로젝트마다 동일 기술의 이름을 별도 문자열로 관리하지 않는 방향이다.
- 기술명과 블로그 해시태그는 역할이 다르므로 자동으로 같은 항목으로 취급하지 않는다.
- 첨부 프로필은 기술 아이콘 + 이름 표시를 참고한다. 실제 기술 목록, 아이콘 공급 방식, 중복 이름/변경/삭제 정책은 후속 설계한다.

## 3. Blog

사용자 지정 기본 정보:

- 제목
- 생성일시 / 수정일시
- 해시태그
- 관련 내부 블로그글들

기술 명칭 재사용 요구에 따라 블로그에서도 공통 기술을 선택할 수 있다. 기존 Markdown 본문, Draft/Published 관리, 복수 Category/Tag 요구는 이번 요청에서 삭제 지시가 없으므로 유지한다. 본문은 Project와 같은 제목 + Markdown 섹션으로 구성하고 추천 질문 블록을 지원한다. 클릭 시 새 채팅을 열어 즉시 전송한다. Project 제목 프리셋을 Blog에도 적용할지는 별도 설계한다. 해시태그는 기존 Tag를 사용하는 방향으로 해석하며 별도 HashTag 모델을 확정하지 않는다.

## 4. Profile

### 기본 정보

- 소개 한줄 요약
- 프로필 이미지
- 소개글: 상세 소개 본문과 별도의 짧은 소개 문구
- 경력
- 스킬
- GitHub 주소
- Email 주소

### 소개 본문

- Project와 같은 제목 + Markdown 본문 섹션 구조를 사용한다.
- 제목 프리셋은 없고 모두 직접 입력한다.
- 추천 질문 블록을 지원하며 클릭 시 새 채팅을 열고 즉시 전송한다.
- 소개 한줄 요약, 별도의 짧은 소개글, 섹션형 상세 소개 본문을 각각 구분한다.

### 스킬 표시

첨부 이미지의 분류와 기술 아이콘/이름 칩 표현을 참고한다.

- 주력
- 프로젝트 경험
- 넓히는 중
- 협업 도구

이 분류는 프로필에서 기술을 보여주는 맥락이다. 공통 Skill 전체에 동일 등급을 강제하지 않는다. 분류명 고정/편집 여부, 표시 순서와 하단 설명 문구 편집 여부는 후속 설계한다. 이미지의 실제 기술 목록과 경험 설명은 사용자의 경력 사실로 등록하지 않는다.

기존 이름/직무/학력/자격 요구는 최신 목록에서 언급되지 않았다. 삭제로 간주하지 않으며 유지 여부와 노출 범위를 추가 확인한다.

## 5. 데이터 설계에 반영할 방향

- Project의 구조화된 기본 정보, 핵심 요약 리스트 및 상세 섹션을 구분한다.
- Project/Blog/Profile의 섹션은 제목·본문·표시 순서를 표현해야 한다. 공유 테이블/JSON/별도 테이블 여부는 아직 정하지 않는다.
- 추천 질문 블록은 본문 내 위치와 질문 목록을 보존해야 한다. Markdown 확장 문법/파서/저장 방식은 개발 설계에서 검증한다.
- Skill은 공통 기준 데이터로 두고 Project/Blog/Profile에서 참조한다. Profile에서의 분류/순서는 연결 관계의 정보로 검토한다.
- 관련 내부 블로그는 기존 Relation 설계와 연결하며 방향성/역방향 표시 정책을 중복 구현하지 않는다.
- 원본 섹션은 검색용 Document/Chunk와 다르다. Markdown 제목을 청킹에 활용할 수 있지만 섹션 하나를 청크 하나로 고정하지 않는다.

## 6. 첨부 이미지 해석 범위

이미지 1은 제목/Markdown/추천 질문 표시, 이미지 2는 스킬 그룹/아이콘/이름 표시를 위한 참고이다. 이미지 안의 SSE, 재귀 CTE, 탐색 깊이, 문서 수 및 기술 경험은 예시 콘텐츠이며 프로젝트 기술 결정이나 실제 포트폴리오 데이터로 채택하지 않는다.
