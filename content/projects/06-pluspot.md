## 프로젝트 개요

플러스팟은 공유 킥보드 충전소를 방문하거나 킥보드를 주차·반납하고 포인트를 받는 앱 서비스입니다. 여기에 광고 사업을 붙이면서 광고주가 가입하고, 광고비를 충전하고, 광고와 쿠폰을 등록·관리할 웹이 필요해졌습니다. 등록된 광고와 쿠폰은 고객 앱의 충전소 페이지나 포인트 획득 페이지 등에 노출됩니다.

저는 웹 프론트엔드를 혼자 맡아 광고주용 웹의 가입·인증부터 광고 등록, 집행 상태와 내역 조회까지 모든 화면을 새로 만들었습니다. 내부 운영자용 관리자 BOS도 맡았는데, BOS는 사내 기존 프로젝트를 클론해 기능을 거의 그대로 썼습니다. 서비스 오픈까지 개발하고 유지보수는 다른 담당자에게 넘겼습니다.

| 항목 | 내용 |
|---|---|
| 팀 구성 | 웹 프론트엔드 1명(본인), 앱 프론트엔드 1명, 서버 2명, 디자이너 1명, PM 1명 |
| 나의 역할 | 광고주용 웹 화면 전 구간 단독 개발, 본인인증·사업자 확인·결제 연동, 내부 운영자 BOS 담당 |

## 주요 성과

- **가입·인증·심사 흐름 구현:** 약관 동의, 본인인증, 사업자 정보, 추가 정보, 완료까지 5단계 가입 화면을 만들고, 심사 상태에 따라 라우트를 나눴습니다. 본인인증은 나이스평가정보로 연동했고, 사업자 정보는 서버 조회 결과에 따라 상호명·개업일·중복 가입 오류를 나눠서 보여 줬습니다.
- **광고비 충전 연동:** 토스페이먼츠 결제위젯으로 결제수단과 약관을 보여 주고, 광고주가 고른 수단으로 광고비 충전 결제를 요청하게 했습니다.
- **광고 등록과 내역 관리:** 배너·체크인 광고, 쿠폰·푸시 등록 화면과 충전·사용 내역 화면을 만들었습니다. 작성하다 화면을 떠나면 확인 모달과 브라우저 이탈 경고를 띄웠고, 광고 상태는 페이지에 들어올 때나 화면 안에서 새로고침할 때 갱신했습니다.
- **서버 요청 실패에도 클라이언트 로그아웃 완료:** 서버 로그아웃 요청이 성공하든 실패하든 계정, 토큰, 심사 상태를 지우고, 잔액·조회 캐시·약관 상태도 같이 초기화했습니다.
- **S3·CloudFront 배포:** GitHub Actions로 정적 파일을 S3에 올리고 CloudFront 캐시를 무효화해 배포했습니다. 개발 서버는 브랜치에 푸시하면, 운영 서버는 워크플로를 수동으로 실행하면 배포됩니다.
