# ADR-0007: Generation Model and Answer Prompt

- Status: Accepted
- Date: 2026-09-10

## Context

ADR-0006이 임베딩 모델과 검색 정책을 다뤘고 생성 모델은 "측정하지 않았다"는 이유로 제외했다. 특히 ADR-0006 결정 3은 "근거 부족 판정을 유사도 임계값이 아니라 생성 단계에서 한다"고 정했는데, 그 생성 단계가 실제로 판단할 수 있는지는 미검증이었다.

`poc/rag_eval.py answer`로 검색 상위 5건을 컨텍스트로 넘겨 답변을 생성하고, 대표 질문 7개에서 ADR-0004의 세 요구(공개 근거만 사용 / 출처 표시 / 근거 부족 명시)를 확인했다.

임베딩과 생성을 별도 ADR로 두는 이유는 되돌리는 비용이 다르기 때문이다. 생성 모델 교체는 프롬프트와 호출부만 바뀌지만, 임베딩 모델 교체는 전체 재임베딩을 요구한다.

## Evidence

`gpt-4.1-mini`, `temperature: 0`, 검색 상위 5건 전달. 답변 원문은 [RAG_MEASUREMENTS](../06-testing/RAG_MEASUREMENTS.md#측정-3--답변-생성)에 있다.

| 질문 | 결과 |
|---|---|
| React Native 프로젝트 경험 | 정확. viora의 RN 앱 개발을 근거와 함께 답변 |
| AI 관련 프로젝트 경험 | 정확. 주요 작업 6항목을 원문 범위 안에서 정리 |
| 폐쇄망 실시간 영상 전송 | 정확. WebSocket 선택 이유와 바이너리 전송까지 포함 |
| 브라우저 USB 직접 통신 | 정확 |
| 오프라인 동기화 충돌 | 정확. **비공개 원문 내용이 섞이지 않음** |
| WebRTC 대신 WebSocket | 정확 |
| OAuth 트러블슈팅 | **"근거에 등록되어 있지 않습니다"로 거부** |

세 가지가 확인됐다.

1. **근거 부족 판정이 생성 단계에서 동작한다.** OAuth 질문은 검색이 유사도 0.342로 각 프로젝트의 "트러블슈팅" 섹션 5건을 넘겼는데도, 모델이 그 근거로는 답할 수 없다고 판단했다. ADR-0006 결정 3의 전제가 검증됐다.

2. **비공개 내용이 답변으로 새지 않는다.** "오프라인 우선 앱에서 동기화 충돌"은 비공개 글 `offline-first-boundary`의 주제와 거의 같은 질문이지만, 답변은 공개 원본 `syncmaster`의 내용만 사용했다. 조회 시점 필터가 검색뿐 아니라 생성 결과까지 지켜준다(RAG-007).

3. **역할 경계가 보존된다.** viora 원문은 "EgoHos 모델 학습은 단독 담당", "하드웨어 2단계는 요구사항 논의 참여"로 기여 수준을 구분한다. 생성된 답변이 이 구분을 그대로 유지했고 논의 참여를 단독 수행으로 승격하지 않았다. 포트폴리오 답변에서 과장은 사실 오류만큼 위험하므로 중요한 성질이다.

## Decision

1. **생성 모델은 `gpt-4.1-mini`, `temperature: 0`으로 시작한다.** 7개 질문에서 근거 준수와 거부 판정이 모두 기대대로 동작했다.

2. **시스템 프롬프트는 ADR-0004의 요구를 그대로 규칙으로 옮긴다.** PoC에서 사용한 형태를 기준으로 한다.
   - 전달된 근거 안의 내용만 사용하고 없는 사실을 만들지 않는다
   - 사용한 근거를 번호로 표시한다
   - 근거가 부족하면 부족하다고 명시하고 추측하지 않는다
   - 근거에 없는 기술·경험을 물으면 등록되어 있지 않다고 답한다

3. **출처 표시 단위는 문서로 한다.** 측정에서 인용 번호가 문서 수준으로는 정확했지만 문장 단위 귀속은 느슨했다. 여러 청크의 내용을 종합한 답변 끝에 관련 근거를 묶어 표시하는 형태였다. 문장별 각주 수준을 요구하지 않고, 답변에 사용된 문서를 링크로 노출하는 방식으로 구현한다.

4. **답변 생성은 검색 결과가 비어 있어도 호출한다.** 근거 없음 문구를 애플리케이션이 하드코딩하지 않고 모델이 생성하게 한다. 컷오프를 두지 않기로 한 ADR-0006 결정 3과 일관된다.

## Alternatives Considered

- **더 큰 생성 모델**: `gpt-4.1-mini`가 거부 판정과 근거 준수를 모두 통과한 상태에서 비용을 올릴 근거가 없다. 답변 품질 불만이 실제로 관측되면 재검토한다.
- **근거 없음을 애플리케이션이 판정**: 검색 결과가 비면 고정 문구를 반환하는 방식. 호출 비용은 줄지만 ADR-0006에서 확인한 대로 "결과가 비는" 경우가 거의 없다. OAuth 질문도 상위 5건이 채워져서 왔다. 애플리케이션이 판정하려면 결국 임계값이 필요하고, 그 임계값을 정할 수 없다는 것이 ADR-0006의 측정 결과다.
- **문장 단위 인용 강제**: 프롬프트로 요구할 수는 있으나 출력이 장황해지고, 현재 UX 요구가 문서 링크 수준이다.

## Consequences

- 근거 없는 질문에도 LLM 호출이 발생한다. 질문당 입력이 근거 5건 기준 대략 1,500~2,000 토큰이다. 챗봇 질문 제한(ADR-0002)이 비용 상한 장치다.
- 프롬프트가 정책의 구현체가 된다. ADR-0004가 바뀌면 프롬프트와 평가 사례를 함께 고쳐야 한다.
- 표본이 질문 7개, 공개 문서 5건이다. 근거를 교묘하게 유도하는 질문, 여러 프로젝트를 비교하는 질문, 대화 이력을 악용하는 질문은 측정하지 않았다.
- 세션 기능이 없어 후속 질문(RAG-005), 세션 분리(RAG-006), 이력 오정보(RAG-008)는 여전히 미측정이다.
- 블로그 3편이 AI 초안이라 문체가 균질하다. 실제 원고로 바꾸면 결과가 달라질 수 있다.
- 2026-09-10 사용자가 네 결정을 그대로 채택했다.

## 후속 결정 — 2026-09-16 (ADR-0013)

근거 부족 시 규칙을 바꿨다: "근거에 등록되어 있지 않다" 대신 설정값 안내 문구(주제는 모델이 채움)를 쓰고, 답변 맨 앞에 `[[NO_ANSWER]]` 표시를 붙인다. 나머지 규칙(근거만 사용, 번호 인용, 추측 금지)은 유지한다. 이 변경 후 PoC 질문 7개를 재측정한다(RAG_MEASUREMENTS).
