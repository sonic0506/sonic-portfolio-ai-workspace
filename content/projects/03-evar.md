## 프로젝트 개요

충전기, 충전소, 회원, 결제, 운영 데이터를 한곳에서 관리하는 전기차 충전 인프라 운영 관리자입니다. 이미 운영 중이던 관리자 페이지를 개선하는 프로젝트였고, 클라이언트를 새로 만들면서 기존 화면의 불편한 점과 업무 흐름도 같이 고쳤습니다.

개발자 2명 중 PL을 맡아 동료와 구조를 함께 논의했고, 관리 영역 전체의 화면 개발을 담당했습니다. 기획·디자인 논의에도 참여해 연관 페이지를 묶어 보여 주는 구성과, 여러 페이지를 오가야 했던 작업을 한 화면에서 이어서 처리하는 방법을 같이 정했습니다. 같은 시기에 진행한 브링앤티와 기술 스택이 같고, FSD·컨벤션·AI 활용 개발 원칙도 똑같이 적용했습니다.

## 주요 성과

- **관리자 클라이언트 전면 재구축:** 운영 중이던 전기차 충전 인프라 서비스를 고도화하면서 관리자 클라이언트를 새로 개발했습니다. 충전기, 충전소, 회원, 결제, 운영 관리까지 모든 영역의 화면을 맡았습니다.
- **연관 관계를 드러내는 페이지 구성:** 기획·디자인 논의에서 기존 관리자 페이지의 불편한 점과 개선 방향을 함께 정리했습니다. GNB에 따로따로 나열돼 관계를 알기 어려웠던 페이지 가운데 상·하위 관계인 것들을 한 페이지로 묶고, 안에서 탭으로 나눴습니다.
- **사용자 화면에서 크레딧 생성·지급 연결:** 원래는 크레딧 페이지에서 크레딧을 만든 뒤 사용자 페이지로 옮겨 가 지급해야 했습니다. 여기에 사용자 크레딧 지급 탭에서 생성부터 지급까지 한 번에 처리하는 경로를 추가했습니다.
- **PL 역할과 구조 공동 논의:** 2인 개발에서 PL로 프로젝트를 이끌었고, 구조는 동료와 함께 논의해 정했습니다.
- **병행 프로젝트와 공통 개발 원칙 적용:** 브링앤티와 같은 FSD·명명 규칙과 AI 활용 개발 원칙을 썼습니다. 규칙, 유형별 예시, 공통 컴포넌트를 기준으로 반복 화면을 만들고, 구현 결과는 사람이 검수했습니다.

## 좋았던 점

### 반복 구현 시간을 줄이고 검수에 집중할 수 있었던 점

예전에는 복사·붙여넣기로 만들던 반복 화면을 AI에 맡기니 개발 시간이 많이 줄었다고 느꼈습니다. 코드 순서나 규칙을 더 잘 지킬 때도 있었습니다.

### 공통 기준을 사람과 AI의 작업에 함께 사용한 점

컨벤션, 유형별 예시 페이지, 공통 컴포넌트를 먼저 만들어 팀에 공유했고, 같은 자료를 AI 작업 기준으로도 썼습니다. 페이지마다 다른 필터·테이블 필드는 디자인 이미지로 전달했고, 기존 유형에 없는 컴포넌트는 따로 개발 업무로 나눴습니다.

구현 전에는 요구사항과 맞는지를, 구현 후에는 코드 규칙과 실제 화면 동작을 확인하도록 단계를 나눴습니다.

## 아쉬운 점

### FSD를 도입한 뒤에도 분류 기준을 구체화해야 했던 점

도메인과 UI를 함께 생각하는 방식에 익숙해지는 데 시간이 걸렸습니다. 처음에는 도메인이 들어간 재사용 컴포넌트를 모두 `widgets`로 분류하다 보니 단순 컨테이너까지 그곳에 쌓였습니다. 나중에 단순 컨테이너는 해당 슬라이스의 `ui`에 두도록 규칙을 바꿨습니다.

패턴을 고른 뒤에도 프로젝트에서 쓰는 컴포넌트의 역할에 맞춰 분류 기준을 계속 다듬어야 했습니다.

### 행위 중심 이름만으로는 도메인별 탐색이 충분하지 않았던 점

`create-admin`, `update-user`처럼 행위가 앞에 오는 슬라이스 이름은 생성·수정별로는 정렬되지만 도메인이 뒤섞였습니다. 중복 확인처럼 CUD로 설명하기 어려운 기능도 있었습니다. 그래서 도메인 아래에 개별 기능을 묶는 2계층 구조를 개선 방향으로 정리했습니다.

### 예시 페이지에 의존한 AI 작업 기준을 더 세분화하고 싶은 점

이번에는 유형별 예시 페이지를 기준으로 AI 개발을 했습니다. 다음에는 라이브러리별 사용 규칙과 공통 컨벤션을 더 잘게 나눠서, 페이지 예시 없이도 필요한 규칙을 찾아 적용하는 방식을 해 보려고 합니다.
