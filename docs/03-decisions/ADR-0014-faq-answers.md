# ADR-0014: FAQ (Registered Question and Answer)

- Status: Accepted
- Date: 2026-09-17

## Context

사용자는 관리자가 등록한 질문·답변으로 답하고, 표현이 다른 같은 뜻의 질문("어디 거주중이신가요?")에도 등록 답변이 나가길 원한다. 측정 5(RAG_MEASUREMENTS)에서 짧은 질문끼리의 임베딩 거리는 같은 뜻과 다른 뜻이 겹쳤다(같은 뜻 최원 0.7338 > 다른 뜻 최근 0.6305). 거리 기준만으로 고정 답변을 내보내면 "어디서 일하세요?"에 "관악구에 삽니다"라고 답할 위험이 있다.

## Decision (2026-09-17 사용자 채택)

1. **FAQ를 RAG 검색 문서(`document_type = 'FAQ'`)로 색인한다.** 질문과 답변을 함께 담는다. 공개 여부는 FAQ의 `published`를 따른다.
2. **같은 뜻인지는 생성 모델이 판단한다.** 근거에 FAQ가 있고 질문과 같은 뜻이면 등록된 답변 문장을 그대로 쓰고 번호로 인용한다. 뜻이 다르면 쓰지 않는다. 거리 기준으로 모델을 건너뛰는 "빠른 길"은 두지 않는다(표본 부족).
3. **등록 방식은 질문 1개(결정 1-A)로 시작한다.** 다른 표현은 별도 테이블(`faq_alias`)에 둘 수 있게 스키마를 미리 만들고, 관리 화면·API는 필요할 때 연다(1-B).
4. 답하지 못한 질문에서 바로 FAQ를 만들 수 있고, 그 질문은 처리됨(RESOLVED)으로 바뀐다.

## Consequences

- FAQ 답변도 모델 호출 비용이 든다. 모델이 등록 문장을 다듬을 수 있으며 완전한 문자 그대로를 보장하지 않는다.
- 공개 사이트에 FAQ 전용 페이지가 없으므로 출처의 `url`은 `null`이다(`type = FAQ`).
- 프롬프트가 바뀌므로(ADR-0007 후속) 실제 모델 재측정 대상에 FAQ 질문을 포함한다.

## 후속 결정 — 2026-09-17 (사용자 선택)

- 등록 질문과 뜻이 비슷한 질문(예: "고향이 어디세요?" 등록, "어디서 태어나셨나요?" 질문)에는 등록 답변만 쓰고 안내 문구·미답변 기록을 붙이지 않는다.
- 계기: 사용자 확인에서 등록 답변과 "태어난 곳은 답변드리기 어려워요" 안내가 함께 나왔다. 프롬프트 FAQ 규칙에 "비슷한 질문이면 표시와 안내 문장을 쓰지 않는다"를 추가했다. 뜻이 다른 질문(사는 곳 ↔ 일하는 곳)은 기존대로 쓰지 않는다.
- 실제 모델 재확인 필요(유료): 비슷한 질문, 다른 뜻 질문, 여러 내용을 묻는 질문.

## 후속 결정 2 — FAQ 판정 단계 분리 (2026-09-17 사용자 선택)

- 문제: 프롬프트 규칙만으로는 같은 질문("어디서 태어나셨나요?")에 등록 답변을 쓸 때와 안 쓸 때가 갈렸고, "근거에 직접적인 언급은 없습니다", "대신할 수 있습니다" 같은 판단 과정이 답변에 섞였다(RAG_MEASUREMENTS 측정 8).
- 결정: 검색 결과(연관 확장 포함)에 공개 FAQ가 있으면 답변 생성 전에 모델에게 "같은 정보를 묻는 등록 질문 번호(없으면 0)"만 따로 묻는다(`FaqMatcher`). 번호가 나오면 서버가 등록 답변을 그대로 보내고 생성은 하지 않는다. 0이면 기존 생성 경로(FAQ도 근거로 포함)로 간다.
- 판정 기준: 표현이 달라도 원하는 정보가 같으면 같은 질문(고향 ↔ 태어난 곳·출신), 다른 정보면 다른 질문(사는 곳 ↔ 일하는 곳), 다른 내용을 함께 물으면 같은 질문이 아니다. 다른 표현(alias)도 판정 목록에 함께 보낸다.
- 비용: FAQ가 검색됐을 때만 짧은 호출 1회가 추가된다. 판정 모델은 답변과 같다(gpt-4.1-mini, temperature 0).
- 답변 프롬프트에 "판단 과정을 쓰지 않는다" 규칙도 추가했다.
