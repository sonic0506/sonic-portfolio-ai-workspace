## 개요

| 항목 | 내용 |
|---|---|
| 유형 | 기술 적용 범위 조율 |
| 시점 | 랜딩 페이지 리뉴얼과 이벤트 페이지 신규 개발 시기 |
| 상태 | 이벤트 페이지에 React 적용, 랜딩 페이지는 기존 스택으로 리뉴얼 |
| 관련 영역 | 랜딩 페이지, 이벤트 페이지, Maven 빌드 |
| 나의 역할 | React 전환 제안, 적용 범위 절충, Maven 빌드 설정 |

## 1. 상황과 제약

기존 서비스는 서버가 렌더링한 Thymeleaf·JSP 템플릿 페이지마다 Vue.js를 인라인으로 불러 쓰는 구조였습니다. SPA 구조는 아니었고, Vue는 라이프사이클 같은 개발 편의 기능을 쓰는 라이브러리로 활용했습니다. 저에게는 새로운 환경이었습니다.

## 2. 검토와 판단

처음에는 제게 익숙한 React로 리뉴얼까지 함께 옮기자고 제안했습니다. 하지만 계약상 리뉴얼은 기존 스택을 유지해야 했고, 그래서 적용 범위를 나눴습니다.

| 대상 | 적용 스택 |
|---|---|
| 기존 랜딩 페이지 (전면 리뉴얼) | Thymeleaf + Vue.js 유지 |
| 새로 여는 이벤트 페이지 | React |

## 3. 실행과 조율

- 랜딩 페이지는 기존 스택으로 전체를 새로 만들었습니다.
- 이벤트 페이지는 React로 개발했습니다.
- Maven 빌드 과정에 React 빌드를 넣고, 산출물이 서버가 찾는 `index.html` 위치에 놓이도록 Maven 설정을 조정했습니다.

프론트엔드는 저 혼자였기 때문에 빌드 설정까지 직접 맡았습니다.

## 4. 결과와 확인

랜딩 페이지는 계약 조건대로 기존 스택으로 리뉴얼했고, 이벤트 페이지는 React로 만들어 기존 Spring 배포 흐름 안에서 함께 배포되게 했습니다.
