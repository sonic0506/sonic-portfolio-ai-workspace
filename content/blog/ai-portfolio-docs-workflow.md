## 개요

| 항목 | 내용 |
|---|---|
| 유형 | AI 활용 |
| 시점 | 2026.09 (프로젝트 시작부터) |
| 상태 | 프로젝트 전 기간 적용 중 |
| 관련 영역 | 개발 프로세스, 설계 문서, ADR |
| 나의 역할 | 규칙 설계, 결정 채택, 측정 실행과 화면 확인 |

## 1. 상황과 제약

혼자 하는 프로젝트라 설계와 구현의 상당 부분을 Claude Code와 Codex에게 맡겼습니다. AI 도구는 세션이 끝나면 앞의 대화를 기억하지 못하고, 두 도구가 서로의 작업 내용을 알지도 못합니다. 그대로 두면 새 세션마다 이미 정한 기술 스택이나 결정을 다시 가정하거나 뒤집을 수 있었습니다.

## 2. 검토와 판단

대화 기억 대신 저장소의 문서를 단일 기준으로 삼았습니다.

- `docs/` 아래에 프로젝트 정의, 설계, 결정(ADR), 계획, 테스트, 세션 인계 문서를 두었습니다.
- Codex가 읽는 `AGENTS.md`와 Claude Code가 읽는 `CLAUDE.md`는 같은 공통 규칙을 가리키는 입구로만 두었습니다.
- 중요한 기술 결정은 ADR로 남기고, 새 세션은 기술 스택을 가정하지 말고 ADR을 먼저 확인하게 했습니다.

## 3. 실행과 조율

- 새 세션은 공통 규칙, 현재 상태, 다음 작업 문서를 읽고 이번 작업 범위를 요약한 뒤 시작합니다.
- 작업을 마칠 때는 세션 로그, 현재 상태, 다음 작업 문서를 갱신합니다. 다음 작업은 "RAG 개발 계속"이 아니라 바로 실행할 수 있을 만큼 구체적으로 적게 했습니다.
- 측정값은 측정 문서 한 곳에만 두고 다른 문서는 링크만 걸게 해서, 수치가 문서마다 달라지지 않게 했습니다.
- ADR에는 누가 제안했고 누가 채택했는지를 적었습니다. AI가 낸 안이라도 채택 여부는 제가 측정 결과와 문서를 보고 정했습니다.
- 실제 OpenAI 호출이 필요한 측정과 화면 확인은 제가 직접 실행해 결과를 문서에 반영했습니다.

## 4. 결과와 확인

약 3주 동안 두 도구와 여러 세션을 오가며 ADR 15건을 남겼고, 새 세션도 문서만 읽고 이어서 작업할 수 있었습니다. 백엔드 120건, 프론트엔드 37건의 테스트를 유지했습니다.
