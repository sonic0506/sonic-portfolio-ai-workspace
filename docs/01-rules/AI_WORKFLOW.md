# AI Workflow

Codex와 Claude Code 모두 아래 순서를 동일하게 따른다.

## A. 새 세션 시작

1. `COMMON_RULES.md` 읽기
2. `CURRENT_STATE.md` 읽기
3. `NEXT_ACTIONS.md` 읽기
4. 사용자 요청과 관련된 설계/결정 문서 읽기
5. 현재 상태와 이번 작업 범위를 짧게 정리
6. 작업 시작

## B. 작업 중

- 새로운 기술 결정이 필요하면 기존 ADR을 검색한다.
- 결정이 없으면 ADR 후보로 기록한다.
- 요구사항이 바뀌면 구현보다 문서 일관성을 먼저 확인한다.
- 큰 작업은 `CURRENT_PLAN.md`의 체크 가능한 작업으로 나눈다.
- 완료한 작업은 즉시 계획 문서에서 상태를 갱신한다.

## C. 작업 종료

### SESSION_LOG에 추가
- 날짜/세션
- 수행 작업
- 변경 파일
- 주요 결정
- 테스트/검증 결과
- 미해결 이슈

### CURRENT_STATE 갱신
현재 저장소의 실제 상태만 요약한다.

### NEXT_ACTIONS 갱신
다음 세션에서 바로 실행할 수 있을 정도로 구체적으로 작성한다.

예:
좋지 않음:
- RAG 개발 계속

좋음:
- `RAG_DESIGN.md`의 Document/Chunk 모델을 기준으로 ERD 초안을 확정한다.
- Chunk metadata 필드 후보를 실제 프로젝트 샘플 2개로 검증한다.

## D. 새 세션용 인계 기준

다음 세션의 AI는 이전 대화를 모른다고 가정한다.

따라서 아래 질문에 문서만으로 답할 수 있어야 한다.

- 이 프로젝트는 무엇인가?
- 지금 어느 단계인가?
- 무엇이 이미 결정되었나?
- 어떤 파일/기능이 구현되었나?
- 무엇이 미완료인가?
- 다음에 무엇을 해야 하나?
- 최근 작업에서 주의할 점은 무엇인가?
