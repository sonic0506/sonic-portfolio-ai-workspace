## 프로젝트 개요

EVAR는 완속·급속 충전기와 충전 인프라 운영 서비스를 제공하는 전기차 충전 솔루션 기업입니다. 충전 인프라 구축부터 충전기·충전소 상태 관리, 충전 서비스 운영까지 맡아 사용자가 안정적으로 충전할 수 있도록 지원합니다.

EV SQUARE는 이 충전 인프라를 운영하기 위한 통합 관제 시스템이자 관리자 웹 플랫폼입니다. 운영자는 여기서 충전기와 충전소의 상태, 이용 현황을 확인하고, 서비스 운영에 필요한 정보를 관리하며 장애에 대응합니다.

이 프로젝트에서는 기존 EV SQUARE를 새로 개발했습니다. 운영자가 복잡한 충전 인프라 정보를 쉽고 빠르게 파악할 수 있도록 UI/UX와 화면 구성 설계에 중점을 두었습니다. 프로젝트 종료 후에는 EVAR 내부 개발자가 바로 개발과 운영을 이어받을 수 있도록 코드 구조와 개발 규칙을 정리하고 인수인계를 진행했습니다.

## 주요 성과

- **관리자 페이지 정보 구조 개선**: 기존 관리자 페이지의 사용 흐름을 분석하고, 기획·디자인 단계부터 개선 방향을 함께 논의했습니다. GNB에 따로 나뉘어 있던 상·하위 관계의 기능을 한 페이지로 묶고 탭으로 나눠, 정보 사이의 연관성을 쉽게 파악할 수 있게 했습니다.
- **크레딧 생성·지급 흐름 통합**: 크레딧 생성과 사용자 지급은 서로 다른 페이지에서 처리해야 했습니다. 사용자 크레딧 지급 화면에 생성부터 지급까지 한 번에 처리하는 경로를 추가해, 운영자가 페이지를 오가지 않아도 되게 했습니다.
- **병행 프로젝트와 개발 구조 통일**: 함께 진행하던 프로젝트와 같은 FSD 구조와 명명 규칙을 적용했습니다. 공통 컴포넌트와 반복 로직은 재사용할 수 있게 묶어, 기능을 추가할 때 같은 코드를 다시 쓰지 않도록 했습니다.
- **AI를 활용한 관리자 화면 개발**: 반복적인 관리자 화면은 개발 규칙, 페이지 유형별 구현 예시, 공통 컴포넌트를 기준으로 AI가 만들게 하고 결과는 사람이 검수했습니다. 반복 구현이 줄어 개발 속도가 빨라졌습니다.
- **프론트엔드 PL로 개발 기준 정리**: 프론트엔드 개발자 2명 중 PL을 맡았습니다. 프로젝트 구조는 동료 개발자와 함께 논의해 정했고, 공통 개발 규칙 정리와 작업 분배, 일정 조율은 제가 맡아 두 사람이 같은 기준으로 개발하게 했습니다.

## 좋았던 점

### 반복 구현 시간을 줄이고 검수에 집중할 수 있었던 점

예전에는 복사·붙여넣기로 만들던 반복 화면을 AI에 맡기니 개발 시간이 많이 줄었다고 느꼈습니다. 코드 순서나 규칙을 더 잘 지킬 때도 있었습니다.

### 공통 기준을 사람과 AI의 작업에 함께 사용한 점

컨벤션, 유형별 예시 페이지, 공통 컴포넌트를 먼저 만들어 팀에 공유했고, 같은 자료를 AI 작업 기준으로도 썼습니다. 페이지마다 다른 필터·테이블 필드는 디자인 이미지로 전달했고, 기존 유형에 없는 컴포넌트는 따로 개발 업무로 나눴습니다.

구현 전에는 요구사항과 맞는지를, 구현 후에는 코드 규칙과 실제 화면 동작을 확인하도록 단계를 나눴습니다.

## 아쉬운 점

### FSD를 도입한 뒤에도 분류 기준을 구체화해야 했던 점

도메인과 UI를 함께 생각하는 방식에 익숙해지는 데 시간이 걸렸습니다. 처음에는 도메인이 들어간 재사용 컴포넌트를 모두 `widgets`로 분류하다 보니 단순 컨테이너까지 그곳에 쌓였습니다. 나중에 단순 컨테이너는 해당 슬라이스의 `ui`에 두도록 규칙을 바꿨습니다.

패턴을 고른 뒤에도 프로젝트에서 쓰는 컴포넌트의 역할에 맞춰 분류 기준을 계속 다듬어야 했습니다.

### 행위 중심 이름만으로는 도메인별 탐색이 충분하지 않았던 점

`create-admin`, `update-user`처럼 행위가 앞에 오는 슬라이스 이름은 생성·수정별로는 정렬되지만 도메인이 뒤섞였습니다. 중복 확인처럼 CUD로 설명하기 어려운 기능도 있었습니다. 그래서 도메인 아래에 개별 기능을 묶는 2계층 구조를 개선 방향으로 정리했습니다.

### 예시 페이지에 의존한 AI 작업 기준을 더 세분화하고 싶은 점

이번에는 유형별 예시 페이지를 기준으로 AI 개발을 했습니다. 다음에는 라이브러리별 사용 규칙과 공통 컨벤션을 더 잘게 나눠서, 페이지 예시 없이도 필요한 규칙을 찾아 적용하는 방식을 해 보려고 합니다.
