# ADR-0018: Category-level Chat (RAG) Scope

- Status: Accepted
- Date: 2026-10-05

## Context

블로그에 성격이 다른 글이 섞였다. 프로젝트에서 실제로 겪은 경험 글(노션 위키 결정 문서 24개)과, 개념을 정리한 학습 글(학습 노트 59개, AI 도구 학습 노트 15개)이다. 채팅은 공개 문서를 모두 근거로 써 왔기 때문에(D4·E5, 2026-10-05), "RAG 경험 있나요?" 같은 질문에 학습 글이 근거로 뽑혀 경험처럼 섞여 답할 위험이 있었다.

사용자는 카테고리를 경험(트러블슈팅·기술선택·협업)과 학습(그 밖)으로 나누고, 카테고리마다 채팅 근거로 쓸지 고를 수 있기를 원했다.

## Decision

- `category.rag_enabled`(V6, 기본 `true`)를 둔다. `false`인 카테고리에 속한 블로그 글은 채팅 근거가 아니다.
- 거르는 시점은 **검색 시점**이다. `Retriever`의 벡터 검색과 참고 관계 확장 두 쿼리에 같은 조건을 둔다. ADR-0005의 공개 범위(조회 시점 필터)와 같은 방식이라 켜고 끌 때 재색인이 필요 없다. 색인은 그대로 둔다.
- 카테고리가 없는 문서(프로젝트, 프로필, FAQ)는 항상 근거다.
- 관리 API `CategoryRequest`/`CategoryResponse`에 `ragEnabled`를 더한다. 요청에서 빠지면 생성 시 `true`, 수정 시 기존 값 유지. 공개 API에는 내보내지 않는다. 어드민 분류 화면에 "채팅 반영" 체크박스를 둔다.
- 시드는 `taxonomy.md` 카테고리 표의 `rag` 열을 읽는다.
- 초기값(2026-10-05 사용자 결정): 트러블슈팅·기술선택·협업만 `true`, 프론트엔드·백엔드·AI·아키텍처·배포·인프라·AI 도구는 `false`. 학습 글은 사이트에는 보이지만 채팅 근거에서는 빠진다. D4·E5(학습 글 채팅 포함)는 이 결정으로 바뀐다.

## Alternatives Considered

### 색인 시점에 제외(문서를 색인하지 않거나 `visible`을 끔)
- 장점: 검색 쿼리가 단순하다.
- 단점: 켜고 끌 때마다 재색인(임베딩 비용)이 든다. `visible`을 쓰면 공개 여부와 뜻이 섞인다.

### 문서 종류나 글 단위로 지정
- 단점: 글마다 고르면 관리할 것이 많다. 사용자가 카테고리를 경험/학습 경계로 정했으므로 카테고리 단위면 충분하다.

## Consequences

- 검색 쿼리마다 `blog_post`·`category`를 한 번 더 조회한다(문서 수 백 건 규모라 무시할 수준, 실측 안 함).
- 꺼진 카테고리의 글은 채팅에서 출처로도 나오지 않는다. 이미 저장된 대화 기록의 출처는 그대로 남는다.
- 학습 글을 다시 근거로 쓰려면 어드민에서 카테고리를 켜면 바로 반영된다.
