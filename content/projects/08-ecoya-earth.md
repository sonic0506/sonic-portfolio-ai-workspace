## 프로젝트 개요

에코야 얼스는 에이치알엠(HRM)의 자원순환 서비스로, 재활용품을 쉽게 분리배출하고 수거받을 수 있게 해 줍니다. 사용자는 모바일 앱에서 페트병, 캔, 우유팩, 멸균팩, 폐전선 등의 수거를 신청하고, 참여한 만큼 얼스 크레딧과 탄소중립 포인트를 적립합니다.

앱에는 수거 신청 외에 챌린지, 커뮤니티, 매거진, 기부와 응모 기능이 있어 사용자가 일상에서 친환경 활동을 꾸준히 이어 갈 수 있습니다.

프로젝트 초기 기획 단계부터 웹 개발에 참여했습니다. 웹 작업은 관리자 웹·앱 내 콘텐츠 WebView, 제휴사 웹앱, B2C 랜딩 페이지의 세 프로젝트로 나누어 진행했습니다.

제휴사 웹앱은 파트너사가 자사 고객에게 에코야 얼스의 수거 서비스를 제공할 때 쓰는 모바일 브라우저용 웹입니다. 제휴사마다 제공하는 서비스가 달라서, 노출할 탭과 수거 가능 품목 등을 관리자 페이지에서 설정하면 그 설정에 맞춰 화면이 구성되도록 만들었습니다.

## 주요 성과

- **관리자·제휴사·B2C 클라이언트 개발**: React로 관리자 웹, 제휴사용 웹앱, 응모·기부 콘텐츠 WebView를 만들고, Next.js로 B2C 랜딩 페이지를 만들었습니다.
- **콘텐츠 템플릿과 미리보기 구조 설계**: 관리자가 설정한 콘텐츠가 제휴사 웹과 B2C 앱에서 같은 규칙으로 보이도록 HTML 템플릿, 데이터 치환, 미리보기 구조를 직접 설계했습니다. 클라이언트마다 필요한 공통 로직은 함수로 묶어 재사용할 수 있게 했습니다.
- **제휴사별 전용 링크와 서비스 구성**: 관리자에서 제휴사를 등록하면 전용 링크가 생성되고, 제휴사별 설정에 따라 제공 서비스가 구성되도록 만들었습니다. 유입 플래그는 서버에서 검증하도록 연계해 제휴사마다 노출되는 서비스 범위를 제어했습니다.
- **모바일 화면 동작 구현과 실기기 검수**: 모바일 브라우저에서 뒤로가기, 바텀시트, 여러 단계 입력, 작성 중 이탈이 일어나는 상황에 맞춰 화면 동작을 구현하고, Android·iOS 실기기로 검수했습니다.
- **S3·CloudFront 배포 자동화**: Amazon S3와 CloudFront로 웹 배포 환경을 구성하고, GitHub Actions로 빌드·배포와 CloudFront 캐시 무효화를 자동화해 반복되던 수동 배포 작업을 줄였습니다.

## 좋았던 점

### 여러 클라이언트가 함께 쓰는 구조를 직접 설계해 본 점

앱과 제휴사 웹이 같은 콘텐츠를 같은 규칙으로 보여 줘야 해서 템플릿, 데이터 치환, 미리보기 구조를 처음부터 설계했습니다. 데이터 호출은 각 클라이언트가 자기 환경에 맞게 하도록 두고, 공통으로 맞출 부분은 템플릿의 화면 구성과 버튼 이벤트를 주고받는 방식 정도로 좁혔습니다. 로그인이나 데이터 처리 방식이 서로 달라도 화면과 이벤트 규칙만 맞추면 되어서, 앱과 웹이 각자 작업하면서도 같은 결과를 낼 수 있었던 점이 좋았습니다.

### 운영 설정이 화면으로 이어지는 흐름을 끝까지 맡아 본 점

제휴사 등록 기능부터 전용 링크 생성, 서버 검증, 제휴사별로 다른 서비스가 보이는 화면까지 한 흐름으로 만들었습니다. 운영자가 관리자에서 고른 값이 사용자 화면에 어떻게 반영되는지 백엔드와 맞춰 가면서 서비스 전체가 돌아가는 방식을 더 넓게 이해하게 됐습니다.

### 모바일 브라우저 사용자의 입장에서 화면 동작을 다듬어 본 점

제휴사 웹앱은 휴대폰 브라우저로 쓰는 서비스라 뒤로가기, 바텀시트, 여러 단계 입력, 작성 중 이탈 같은 작은 동작이 사용감을 크게 좌우했습니다. 사용자가 실제로 어떻게 조작할지를 먼저 떠올리며 화면 흐름을 설계했고, Android와 iOS 실기기로 직접 써 보며 확인했습니다. 이 과정에서 모바일 웹의 사용성을 보는 눈이 생겼습니다.

## 아쉬운 점

### 오픈 이후의 운영과 유지보수를 길게 경험하지 못한 점

계약 범위가 초기 개발과 인수인계 중심이어서 오픈 뒤 유지보수는 초반에 짧게만 맡았습니다. 기간이 짧다 보니 사용자 피드백을 모아 화면을 개선하거나 운영하면서 반복해서 생기는 문제에 대응해 볼 시간은 없었습니다.

직접 설계한 콘텐츠 템플릿 구조와 제휴사별 서비스 구성이 운영에서 어떻게 쓰였는지 끝까지 확인하지 못한 점이 특히 아쉽습니다. 제휴사가 늘어나거나 관리자가 콘텐츠를 자주 바꿀 때도 구조가 잘 버텼는지, 모바일 브라우저에서 미처 생각하지 못한 불편은 없었는지 알고 싶었습니다. 다음 프로젝트에서는 오픈 이후까지 길게 참여해서 제가 만든 구조가 실제로 어떻게 쓰이는지 보고 개선까지 해 보고 싶습니다.
